# 一稿多发：多平台改写

| 项目 | 内容 |
|---|---|
| 方向 | 📱 自媒体运营 |
| 版本 | v1.0 · 2026-11-12 |
| 结构 | VICTORY 七段式 |
| 适用模型 | ChatGPT / Claude / Gemini / DeepSeek / Kimi / 豆包 等 |

## 用途

把一篇内容改写成小红书、LinkedIn、X、公众号等不同平台的版本。

## 使用方法

1. 复制下面整段提示词；
2. 把 `{花括号}` 里的变量换成你的真实信息（不知道的写“无”）；
3. 发送给 AI。结果不满意时，用文末的迭代指令修改，不要重写。

## Prompt

```markdown
## V 目标
把一份原始内容改写成多个平台的版本，每个版本都符合平台习惯，而不是简单复制。

## I 角色与受众
你是跨平台内容运营，熟悉中文和海外社媒的风格差异。

## C 背景
- 原始内容：
"""
{source_content}
"""
- 目标平台：{platforms}（例：小红书、LinkedIn、X、公众号、Facebook）
- 每个平台的受众：{audiences}
- 品牌语气：{tone}

## T 任务
为每个平台提炼最适合的角度，再按平台规则改写。参考：小红书重体验和干货清单；LinkedIn 重专业洞察和个人经历；X 重观点和短句；公众号重完整论证。

## O 输出
每个平台一个小节：标题/首句 | 正文 | 话题标签 | 配图建议。海外平台用英文。

## R 规则
- 核心事实与观点保持一致，不新增原文没有的数据。
- 每个版本的开头都要重写，不能相同。
- 遵守各平台字数习惯（如 X 单条 ≤ 280 字符，可写成串）。

## Y 验收标准
① 每个版本单独看都像是为该平台原创的；② 关键信息不丢失；③ 英文版没有中式表达。
```

## Vic 实战提示

长内容先写公众号或 LinkedIn 长文，再用本提示词拆。

## 迭代指令（结果不满意时直接发）

- `保留结构，每一条都换成更具体的例子、数字或场景。`
- `你以目标读者的身份给它打分（10 分制），指出最弱的 3 处并改掉。`
- `给我 3 个风格差异明显的版本，并说明各自适合什么情况。`
