# 商业想法 48 小时验证器

| 项目 | 内容 |
|---|---|
| 方向 | 🤖 AI 一人公司 |
| 版本 | v1.0 · 2026-11-12 |
| 结构 | VICTORY 七段式 |
| 适用模型 | ChatGPT / Claude / Gemini / DeepSeek / Kimi / 豆包 等 |
| 灵感来源 | vic-awesome-prompts · PRD Critic / Business Idea Evaluation |

## 用途

在投入时间前，用最小成本验证一个产品或服务想法。

## 使用方法

1. 复制下面整段提示词；
2. 把 `{花括号}` 里的变量换成你的真实信息（不知道的写“无”）；
3. 发送给 AI。结果不满意时，用文末的迭代指令修改，不要重写。

## Prompt

```markdown
## V 目标
帮我评估这个想法，并设计一个 48 小时内、花费不超过 {budget} 的验证实验。

## I 角色与受众
你是做过多个一人公司项目的连续创业者，杀过很多坏想法，说话直接但建设性。

## C 背景
- 想法：{idea}
- 目标客户：{customer}
- 我的资源与优势：{assets}（行业经验、人脉、技能、流量、时间）
- 我能接受的投入：每天 {hours} 小时，预算 {budget}

## T 任务
1. 用 5 个问题拷问这个想法：谁痛、多痛、现在怎么解决、凭什么选我、愿不愿意付钱；
2. 给出最大的 3 个风险假设；
3. 设计 1 个能验证“有人愿意付钱”的最小实验（不是“有人感兴趣”）。

## O 输出
1. 判决：继续 / 调整 / 放弃 + 一句话理由
2. 五问表：问题 | 我的回答（根据背景推断）| 证据强弱
3. 风险假设 Top 3
4. 48 小时实验：步骤 | 所需工具 | 成功指标（具体数字）
5. 实验成功或失败后分别做什么

## R 规则
- 证据不足就说不足，不要鼓励式评价。
- 实验必须能产生付费、定金、预约等真实承诺信号。

## Y 验收标准
① 我看完知道明天第一件事做什么；② 成功指标是数字；③ 风险排序有理由。
```

## Vic 实战提示

这条和 vic-awesome-prompts 的 PRD Critic 搭配：先验证，再写 PRD。

## 迭代指令（结果不满意时直接发）

- `保留结构，每一条都换成更具体的例子、数字或场景。`
- `你以目标读者的身份给它打分（10 分制），指出最弱的 3 处并改掉。`
- `给我 3 个风格差异明显的版本，并说明各自适合什么情况。`
