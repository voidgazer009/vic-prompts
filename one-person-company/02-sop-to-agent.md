# SOP → AI 工作流拆解器

| 项目 | 内容 |
|---|---|
| 方向 | 🤖 AI 一人公司 |
| 版本 | v1.0 · 2026-11-12 |
| 结构 | VICTORY 七段式 |
| 适用模型 | ChatGPT / Claude / Gemini / DeepSeek / Kimi / 豆包 等 |

## 用途

把一项重复工作拆成可交给 AI / Agent 执行的流程，找出能自动化的部分。

## 使用方法

1. 复制下面整段提示词；
2. 把 `{花括号}` 里的变量换成你的真实信息（不知道的写“无”）；
3. 发送给 AI。结果不满意时，用文末的迭代指令修改，不要重写。

## Prompt

```markdown
## V 目标
把我描述的一项重复工作拆解成 AI 工作流，标出哪些步骤可以交给 AI、哪些必须由我做，并给出每一步的提示词。

## I 角色与受众
你是 AI 自动化顾问，熟悉 ChatGPT、Claude、Agent、Skills、MCP 和常见自动化工具（如 n8n、Zapier、Make）。读者是不会编程的一人公司老板。

## C 背景
- 这项工作：{task}
- 现在的做法（步骤、用到的工具、耗时、频率）：{current_process}
- 我能用的工具与账号：{tools}
- 质量红线：{red_lines}（哪些结果出错代价很大）

## T 任务
1. 把流程拆成 5–10 个步骤，每步标注：输入、输出、是否适合 AI（适合 / 半自动 / 必须人工）及原因；
2. 为适合 AI 的步骤各写 1 条可直接使用的提示词；
3. 设计人工检查点，放在 {red_lines} 相关的步骤后。

## O 输出
1. 流程表：步骤 | 输入 | 输出 | 执行者 | 原因 | 预计节省时间
2. 每步提示词（代码块）
3. 自动化升级路线：现在（手动复制粘贴）→ 下一步（模板/Skill）→ 最终（Agent / 自动化工具）

## R 规则
- 不推荐需要编程才能完成的方案，除非我在 {tools} 里写了会编程。
- 涉及发送邮件、付款、对外发布的步骤，一律设为“AI 起草 + 人工确认”。

## Y 验收标准
① 每个步骤的输入输出能衔接；② 我今天就能用前 2 条提示词；③ 节省时间有估算依据。
```

## Vic 实战提示

把你最烦的一件事先拆，比如“每周整理询盘”“每天发 3 条社媒”。

## 迭代指令（结果不满意时直接发）

- `保留结构，每一条都换成更具体的例子、数字或场景。`
- `你以目标读者的身份给它打分（10 分制），指出最弱的 3 处并改掉。`
- `给我 3 个风格差异明显的版本，并说明各自适合什么情况。`
