# 元提示词：提示词 / Skill 生成器

| 项目 | 内容 |
|---|---|
| 方向 | 🤖 AI 一人公司 |
| 版本 | v1.0 · 2026-11-12 |
| 结构 | VICTORY 七段式 |
| 适用模型 | ChatGPT / Claude / Gemini / DeepSeek / Kimi / 豆包 等 |

## 用途

描述一个需求，让 AI 帮你写出 VICTORY 结构的专业提示词，或封装成 Agent Skill。

## 使用方法

1. 复制下面整段提示词；
2. 把 `{花括号}` 里的变量换成你的真实信息（不知道的写“无”）；
3. 发送给 AI。结果不满意时，用文末的迭代指令修改，不要重写。

## Prompt

```markdown
## V 目标
把我描述的需求写成一份可反复使用的高质量提示词；如果我选择 Skill 模式，再封装成 SKILL.md 格式。

## I 角色与受众
你是提示词工程师，熟悉 2026 年主流模型（GPT、Claude、Gemini 及国产模型）的写法。使用者是不懂技术的业务人员。

## C 背景
- 我的需求：{need}
- 使用场景与频率：{scenario}
- 好结果的样例（如有）：{good_example}
- 输出模式：{mode}（普通提示词 / Skill）

## T 任务
1. 先问我最多 3 个关键问题，补齐缺失信息（信息已足够则跳过）；
2. 按 VICTORY 结构写提示词：V 目标、I 角色与受众、C 背景、T 任务、O 输出、R 规则（附原因）、Y 验收标准；
3. 把会变化的内容抽成 {变量}；
4. Skill 模式下，额外输出 SKILL.md：开头 YAML（name、description：一句话写清“做什么 + 什么时候用”），正文写使用步骤和注意事项。

## O 输出
1. 完整提示词（代码块）
2. 变量说明表：变量 | 含义 | 示例
3. 1 组测试输入，以及预期结果应满足的标准
4.（Skill 模式）SKILL.md 全文

## R 规则
- 不使用全大写强调、“一步一步思考”、“检查两遍”等过时写法，因为新模型会过度执行。
- 规则之间不能互相矛盾；有冲突时写明优先级。

## Y 验收标准
① 换一组变量也能直接用；② 新人照着变量说明就能填写；③ 每条规则都有原因。
```

## Vic 实战提示

这是本仓库的“母提示词”，其他 19 条都可以用它迭代出新版本。

## 迭代指令（结果不满意时直接发）

- `保留结构，每一条都换成更具体的例子、数字或场景。`
- `你以目标读者的身份给它打分（10 分制），指出最弱的 3 处并改掉。`
- `给我 3 个风格差异明显的版本，并说明各自适合什么情况。`
