# 物流异常通知（延误 / 查验 / 丢件）

| 项目 | 内容 |
|---|---|
| 方向 | 🚢 国际物流 |
| 版本 | v1.0 · 2026-11-12 |
| 结构 | VICTORY 七段式 |
| 适用模型 | ChatGPT / Claude / Gemini / DeepSeek / Kimi / 豆包 等 |
| 灵感来源 | vic-awesome-prompts · Customer Support Reply Drafter |

## 用途

货物出现异常时，给客户发一封既专业又不引发恐慌的通知。

## 使用方法

1. 复制下面整段提示词；
2. 把 `{花括号}` 里的变量换成你的真实信息（不知道的写“无”）；
3. 发送给 AI。结果不满意时，用文末的迭代指令修改，不要重写。

## Prompt

```markdown
## V 目标
写一封物流异常通知，让客户第一时间了解情况、知道我们在处理，并减少投诉。

## I 角色与受众
你是货代公司的客服主管，擅长危机沟通。收件人：{customer}，他关心的是货什么时候到、会不会多花钱、要不要他做什么。

## C 背景
- 运单信息：{shipment_info}（单号、船名航次/航班、货物）
- 异常情况（事实）：{facts}
- 已采取的措施：{actions}
- 预计影响：{impact}（时效、费用）
- 公司政策：{policy}（赔付、费用承担）

## T 任务
按“发生了什么 → 影响 → 我们在做什么 → 需要客户做什么 → 下次更新时间”的顺序写通知。

## O 输出
- 中文版 + {language} 版
- 每版 ≤ 180 字/词
- 标题清楚标明单号和事件

## R 规则
- 只陈述 {facts} 中的事实，不推测原因，不编造时间和单号。
- 不承诺 {policy} 以外的赔偿。
- 不甩锅给船司或海关，用中性表达说明原因。

## Y 验收标准
① 客户读完知道下一步是什么、什么时候会收到更新；② 没有任何未经确认的承诺；③ 语气冷静、负责。
```

## Vic 实战提示

异常发生 1 小时内发第一封，比内容完美更重要。

## 迭代指令（结果不满意时直接发）

- `保留结构，每一条都换成更具体的例子、数字或场景。`
- `你以目标读者的身份给它打分（10 分制），指出最弱的 3 处并改掉。`
- `给我 3 个风格差异明显的版本，并说明各自适合什么情况。`
