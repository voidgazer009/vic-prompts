# 货代账单核对与费用争议

| 项目 | 内容 |
|---|---|
| 方向 | 🚢 国际物流 |
| 版本 | v1.0 · 2026-11-14 |
| 结构 | VICTORY 七段式 |
| 适用模型 | ChatGPT / Claude / Gemini / DeepSeek / Kimi / 豆包 等 |
| 灵感来源 | [vic-awesome-prompts · 发票数字与完整性核对](https://github.com/voidgazer009/vic-awesome-prompts/blob/main/collection/logistics/invoice-checker.md)（CC0），按货代 Debit Note、报价对照和海外费用规则重写 |

## 用途

收到货代、船公司或仓库的账单（Debit Note）后，对照当初的报价和实际单证，逐项核对金额、重复收费和不合理费用，并写出有依据、不得罪人的费用质询邮件。

## 使用方法

1. 复制下面整段提示词；
2. 把 `{花括号}` 里的变量换成真实信息（不知道的写“无”）；账单和报价可直接粘贴文字；
3. 发送给 AI。结果不满意时，用文末的迭代指令修改，不要重写。

## Prompt

```markdown
## V 目标
帮我核对下面这份物流账单：每一笔金额算得对不对、和报价是否一致、有没有重复或报价外的费用，并写好发给对方的质询邮件。目标是只付该付的钱，同时不伤和供应商的关系。

## I 角色与受众
你是有 10 年经验的物流成本核算专员，熟悉海运、空运、拖车、仓储的常见费用（如海运费、THC、文件费、BAF/CAF、滞箱费、滞港费、改单费、拖车费）。
结果给我（货主 / 物流经理）看；质询邮件发给对方的客服或财务。

## C 背景
- 我的身份：{my_role}（货主 / 货代 / 跨境卖家）
- 货物与运输：{shipment_info}（起运港、目的港、箱型箱量或计费重量、运输方式、提单号 / 运单号）
- 币种与结算汇率约定：{currency_note}
- 当初的报价或合同费用条款：
"""
{quotation}
"""
- 对方发来的账单：
"""
{bill}
"""
- 实际发生的关键日期与事实（到港日、提货日、还柜日、免用箱天数、改单次数等）：{facts}
- 语气偏好：{tone}（温和 / 中性 / 坚定）；邮件语言：{language}

## T 任务
1. 把账单拆成逐行费用：费用名称、数量、单价、账单金额、币种。
2. 逐行重算 数量 × 单价，再重算小计和总计；能运行代码就用精确小数运算并说明，不能就写出每一步并注明“手算需复核”。
3. 把每一行和报价对照，分为：与报价一致 / 金额不同 / 报价中没有 / 疑似重复 / 信息不足。
4. 对滞箱费、滞港费等和天数有关的费用，用我提供的日期与免用天数复算天数，算不出就说缺什么。
5. 列出必须向对方索取的凭证（如费用明细、船公司账单、放箱与还柜记录）。
6. 写质询邮件。

## O 输出
1. 结果行：“全部一致”或“发现 N 处差异”，并给出争议金额合计（按币种分别写）。
2. 差异表：费用项 | 账单金额 | 重算或报价金额 | 差额 | 类别 | 依据。
3. 需要补充的信息与凭证清单。
4. 质询邮件：Subject + 正文（{language}，≤ 150 词），只质询有依据的项目，写明提单号、费用名称和金额。
5. 可以先付的无争议部分和建议的付款动作（仅建议，不替我决定）。

## R 规则
- 金额、天数、条款只用我提供的材料，缺失写“未提供”，不要编造或估算，因为一个错误数字会让整封质询失去说服力。
- 不判断某项费用在法律或税务上是否合法，也不说“对方违规”，因为你看不到完整合同和当地规定；只写“与报价不一致，请说明依据”。
- 不同币种分别汇总，不自行换算，因为汇率以双方约定或结算日为准。
- 不要静默更正账单，每处差异都列出两个数字，因为我需要拿着原始数字去和对方沟通。
- 不承诺“我们会拒付”“我们将更换货代”等后果，除非我在材料里明确写了，因为业务关系的决定权在我。
- 邮件里只质询有依据的项目；信息不足的项目用提问方式，因为无依据的指责会让对方变得更不配合。
- 不在邮件里写完整银行账号或内部成本价，因为这些属于敏感信息。

## Y 验收标准
① 每一行金额都能用我给的数据复算；② 每处差异都标了类别和依据；③ 邮件只含有依据的项目并带提单号和金额；④ 没有出现我没提供的数字、法规结论或威胁；⑤ 无争议部分和争议部分分得清楚。
```

## Vic 实战提示

每票货的账单一到就跑一遍，别等月结。最容易被多收的是重复的文件费和天数算错的滞箱费，把还柜日期记清楚再贴进来，差异表能直接当谈判底稿。

## 迭代指令（结果不满意时直接发）

- `保留结构，把质询邮件改得更简短，只保留金额最大的 3 项差异。`
- `你以对方财务的身份读这封邮件，指出最可能被他用“报价已含 / 条款已写明”挡回来的 2 处，并补充我该准备的证据。`
- `给我同一封邮件的 3 个版本：温和 / 中性 / 坚定，并说明各自适合什么情况。`
